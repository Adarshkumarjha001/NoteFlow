# NoteFlow — Capture Your Ideas

NoteFlow is a full-stack note-taking application built with the MERN stack. It allows users to create, organize, search, and manage their notes through a clean, responsive interface with secure authentication and light/dark theme support.

**Repository:** [NoteFlow on GitHub](https://github.com/Adarshkumarjha001/NoteFlow)

## Features

### Authentication and Security
- User registration and login
- JWT-based authentication
- Password hashing using bcrypt
- Protected routes and authenticated API access
- Form validation and error handling

### Note Management
- Create, edit, and delete notes
- Pin and unpin important notes
- Mark notes as favorites
- Archive and unarchive notes
- Organize notes by category
- Add tags and choose note colors

### Search and Organization
- Search notes by title, content, and tags
- Separate views for all notes, pinned notes, favorites, and archived notes
- Category-based navigation
- Dashboard statistics for notes, pins, favorites, and archived items

### User Experience
- Responsive interface for desktop, tablet, and mobile
- Light and dark themes
- Loading indicators and toast notifications
- Password visibility toggle
- Reusable React components
- Modern styling with gradients, transitions, and interactive elements

## Prerequisites

Before running the application, install:

- [Node.js and npm](https://nodejs.org/)
- [MongoDB Community Server](https://www.mongodb.com/try/download/community) or a [MongoDB Atlas](https://www.mongodb.com/atlas) database
- [Git](https://git-scm.com/)

Use a Node.js version compatible with the dependencies specified in the project.

## Installation and Setup

### 1. Clone the repository

```bash
git clone https://github.com/Adarshkumarjha001/NoteFlow.git
cd NoteFlow
```

### 2. Configure the backend

Open a terminal in the project root and run:

```bash
cd server
npm install
```

Create a `.env` file inside the `server/` directory. Use the following example and adjust it to your configuration:

```env
PORT=5000
NODE_ENV=development
MONGO_URI=mongodb://127.0.0.1:27017/noteflow
JWT_SECRET=replace_with_a_secure_random_secret
JWT_EXPIRE=7d
CLIENT_URL=http://localhost:5173
```

**Configuration notes:**
- Replace `MONGO_URI` with your own MongoDB connection string if using Atlas.
- Replace `JWT_SECRET` with a strong, randomly generated secret.
- Ensure `CLIENT_URL` matches the frontend origin used by your application.

Start the backend development server:

```bash
npm run dev
```

The backend is expected to run at `http://localhost:5000` when configured with the example port.

### 3. Configure the frontend

Open a second terminal from the project root:

```bash
cd client
npm install
```

Create a `.env` file inside the `client/` directory:

```env
VITE_API_URL=http://localhost:5000
```

Start the frontend:

```bash
npm run dev
```

Open the local URL printed by Vite in the terminal. The default Vite development URL is usually `http://localhost:5173`.

**Important:** Keep the frontend and backend running in separate terminals. If either application uses a different port, update the environment configuration accordingly.

## How to Run the Application

1. Start MongoDB or confirm that your Atlas database is accessible.
2. Start the backend using `npm run dev` from the `server/` directory.
3. Start the frontend using `npm run dev` from the `client/` directory.
4. Open the frontend URL printed in the terminal.
5. Register an account or sign in.
6. Create notes and explore the available management features.

For a quick functional check, create a note, edit it, search for it, pin it, add it to favorites, and test archiving and unarchiving.

## API Overview

The backend provides authentication and note-management endpoints. Verify the exact routes in the server's route files before relying on this reference.

### Authentication

| Method | Endpoint | Purpose |
|---|---|---|
| POST | `/api/auth/register` | Register a new user |
| POST | `/api/auth/login` | Authenticate a user |
| GET | `/api/auth/me` | Retrieve the current user |

### Notes

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/api/notes` | Retrieve notes and supported filters |
| GET | `/api/notes/:id` | Retrieve an individual note |
| POST | `/api/notes` | Create a note |
| PUT | `/api/notes/:id` | Update a note |
| DELETE | `/api/notes/:id` | Delete a note |
| PATCH | `/api/notes/:id/pin` | Toggle pin status |
| PATCH | `/api/notes/:id/favorite` | Toggle favorite status |
| PATCH | `/api/notes/:id/archive` | Toggle archive status |

The notes API supports query parameters for filtering, such as category, pinned status, favorite status, and archived status, subject to the implemented backend logic.

## Security Considerations

- Never commit real `.env` files or credentials.
- Store password hashes rather than plain-text passwords.
- Keep JWT secrets on the backend.
- Validate and sanitize user input appropriately.
- Verify note ownership for operations involving individual notes.
- Use appropriate CORS settings.
- Avoid exposing sensitive server errors in production.
